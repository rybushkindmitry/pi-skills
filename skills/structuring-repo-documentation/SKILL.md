# Structuring Repo Documentation

## Overview

Три раздельных артефакта отвечают на три разных вопроса; смешивать их нельзя.
**История — в git, а не в README.** Изменение решения — новый ADR с
`supersedes`, а не правка старого задним числом.

| Артефакт | Вопрос | Правила |
| --- | --- | --- |
| `docs/adr/` (+ индекс) | **Почему** так | один ADR = одно решение; контекст → решение → альтернативы (с причинами отказа) → последствия (включая минусы) → ссылки; номер навсегда; ревизия = новый ADR с `supersedes: [ADR-NNNN]` |
| `docs/architecture-current.md` / `-target.md` | **Как устроено / куда движемся** | current — только факты из кода и деплоя, дата среза в шапке; target — цели + **гейты переходов**; в шапке nav-файла — таблица приоритета источников |
| `docs/implementation-status.md` | **Что выкачено и когда** | «Обновлено: дата»; датированные записи-свидетельства; заменяется целиком, новые секции не растут; «история — в git» |

## When to Use

- принятое архитектурное решение нужно зафиксировать («мы решили X», «отказались от Y»)
- просят «обновить документацию» / «задокументировать решение»
- README обрастает «Историей изменений» / статусными абзацами
- один файл смешивает «как есть» и «когда-нибудь»

## Common Mistakes (типовые провалы без скилла)

| Ошибка | Как правильно |
| --- | --- |
| Решение → однострочный ченджлог в README | ADR-файл: без контекста и альтернатив через год «почему?» не ответить |
| Дописывать «Историю изменений» в README | README тонкий: что это + ссылки; история — git-лог |
| Переписать overview, оставив планы рядом с фактами | планы → target с гейтами; факты → current с датой среза |
| Отредактировать принятый ADR по новому поводу | `supersedes` новым файлом; уточнение фактов — датированная ревизия в шапке |

## Red Flags — STOP

- Соблазн «это мелочь, ADR не нужен» — если решение меняет стек/структуру/контракты, ADR нужен
- «README-ченджлог уже ведётся, продолжу в нём» — перенеси в implementation-status
- «Добавлю план в current-документ, он рядом» — в target

## Быстрый алгоритм

1. Решение → `docs/adr/adr-NNNN-short-name.md` + строка в индекс `docs/adr/README.md`.
2. Факты кода/деплоя устарели → обнови `architecture-current.md` (новая дата среза).
3. Изменение направления → `architecture-target.md` (цель + гейт).
4. Выкат/приёмка → запись в `implementation-status.md` (дата, свидетельство).
5. README остаётся тонким: обзор + таблица решений со ссылками на ADR + ссылки на доки.

Масштабируй по размеру проекта: в маленьком репо достаточно `docs/adr/` +
тонкого README; триптих current/target/status — когда фактов и планов стало
больше одного экрана.
