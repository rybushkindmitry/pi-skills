# Analyzing YouTube Videos

## Overview

Субтитры дают речь, кадры дают визуал — конспект всегда строится из обоих
источников. Готовые субтитры YouTube быстрее и точнее локальной транскрипции
(Whisper не нужен). Визуал смотрят не «все кадры подряд», а уникальные кадры,
собранные в коллажи.

## When to Use / When NOT

- Use: ссылка на YouTube-видео + просьба изучить/законспектировать/пересказать
  с учётом слайдов и демонстраций; сохранить конспект в базу знаний.
- Not: короткий вопрос «что сказано в видео на 5-й минуте» (хватит субтитров,
  кадры не нужны); аудио-подкасты без видеоряда (кадры бесполезны, только
  субтитры); live-трансляции.

## Workflow

**1. Подготовка (одна команда, всё локально):**

```bash
python3 scripts/prepare.py <URL> --lang en,ru
```

Скрипт сам ставит venv при первом запуске и создаёт в `/tmp/video-digest-<id>/`:
метаданные, `subs_para.txt` (транскрипт агрегированный по ~60 сек) + `subs.txt`
(построчно), видео 720p, уникальные кадры и коллажи `grids/gNN.jpg` (2×2
кадра с подписями файл+таймкод).

Параметры под жанр (важно!):

| Жанр | --interval | --dedup | --max-height | Главный источник |
| --- | --- | --- | --- | --- |
| Доклад/презентация (слайды) | 10 | 5 | 720 | кадры ≈ транскрипт |
| Интервью/подкаст (говорящие головы) | 30 | 8 | 360 (для 3ч+) | транскрипт; кадры — только вставки |

**2. Транскрипт:** читать `subs_para.txt` (длинный — частями через offset).
Построчный `subs.txt` — для поиска точной формулировки по таймкоду.

**3. Визуал:** коллажи просматривать пачками по 3 (read поддерживает
изображения); слайды/схемы с плотным текстом — повторно полным кадром из
`frames/` по `frames_kept.txt`.

**4. Конспект:** разделы с таймкодами, ключевые схемы и цифры дословно; в конце —
выводы. Просили сохранить в базу знаний — заметка в `.agent-knowledge/`
(формат Obsidian, `[[wikilinks]]`, датированное имя), связать с индексами.

## Gotchas (реальные, проверено на 3 видео)

- **HTTP 429 на субтитры через yt-dlp** — обычное дело: fallback на
  `youtube-transcript-api` (в скрипте автоматом), при DNS-сбоях — ретраи с паузой.
- yt-dlp требует `--impersonate chrome`, иначе YouTube режет запросы; warning
  «no JavaScript runtime» — некритичен.
- **Scene detection (`select=gt(scene,...)`) проваливается** на презентациях с
  плавными анимациями и на интервью (даёт 20 кадров на 4 часа) — поэтому
  фиксированный интервал + imagehash-дедупликация.
- Таймкоды длинных видео превышают 59 минут (`[150:05]`) — парсить `mm:ss`
  целиком, не фиксированные позиции.
- Построчный транскрипт 4,5-часового видео (~8000 строк, ~500 КБ) в контекст не
  влезает — только агрегированный, читать частями.
- У видеопотока без аудио размер кадра может отличаться от 1280×720 — коллажи
  скрипт сам масштабирует.

## Common Mistakes

- Начинать с Whisper/транскрипции аудио — почти всегда избыточно и медленно;
  сначала субтитры, Whisper — только если их нет совсем.
- Смотреть кадры по одному — 100+ read-вызовов; только коллажи, одиночные кадры —
  для уточнения.
- Один интервал/порог на все жанры — интервью превращается в 500 дубликатов,
  презентация с порогом 8+ теряет слайды.
- Писать конспект без таймкодов — теряется возможность вернуться к источнику.
