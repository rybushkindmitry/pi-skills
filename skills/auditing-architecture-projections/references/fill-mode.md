# Fill-режим: скелеты недостающих проекций

Читай этот файл только когда человек явно попросил закрыть пробелы
(«сгенерируй скелет NFR», «закрой пробелы» и т.п.). Явный запрос на fill —
это разрешение писать файлы выбранной проекции и только их. Если аудита в
контексте нет — сначала прогони аудит по SKILL.md: скелет наполняется его
фактами.

## Перед записью

1. **Конвенции репо.** Если установлен скилл `structuring-repo-documentation`
   — прочитай его SKILL.md и следуй его конвенциям: принятые решения → ADR с
   датировкой и статусами, текущее состояние → `architecture-current.md`
   (полная замена файла при обновлении). Если скилла нет — используй те же
   конвенции по имени.
2. **Факты.** Скелет наполняется только фактами из аудита (с цитатами
   `файл:строка`). Всё остальное — TODO-плейсхолдеры. Не изобретать факты,
   числа, имена внешних систем, лимиты.
3. **Объём и путь.** Писать только запрошенные проекции. Целевой путь: если
   в репо есть `docs/` — `docs/<slug>.md` в стиле именования репо
   (например `docs/nfr.md`, `docs/data-model.md`); выбранный путь явно назвать
   в ответе. Если `docs/` нет или раскладка нестандартная — предложить путь и
   дождаться подтверждения. Если запрошено несколько проекций — всегда
   сначала список файлов и подтверждение.

## Формат скелета

```markdown
# <Проекция>: <предмет>

Статус: скелет, сгенерирован auditing-architecture-projections <дата>
Вопрос проекции: <вопрос из references/projections.md>

## Что известно из аудита
- <факт> (<файл:строка>)

## TODO
- [ ] <что заполнить и откуда это взять>
```

Секция «Что известно из аудита» может быть пустой — тогда скелет состоит из
структуры и TODO.

## Правила записи

- Не коммитить: файлы остаются в рабочем дереве; коммит решает человек.
- Карту `docs/architecture-coverage.md` fill не трогает: скелет с TODO не
  меняет вердикт; вердикт пересматривает следующий аудит после заполнения
  TODO.
- Существующие документы не переписывать; если найден пересекающийся документ
  — предложить дополнить его, а не создавать дубль.
- Если в ходе fill зафиксировано архитектурное решение — предложить ADR по
  конвенциям из п. 1, отдельным файлом, с явным вопросом человеку.
- Перечислить, что сделано: какие файлы созданы, какие TODO остались.
